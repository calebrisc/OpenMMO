## Description
The patcher module is a tool for applying custom patches to the PokeMMO client.
It replaces the public keys of the PokeMMO servers with the ones generated by the `:keys` module, so the client accepts packets signed by our own servers, and it points the login server at the local machine.
This module is intended for advanced users who understand the risks of modifying game software.

## How to Run

Running is pretty straightforward.

1) Open `gradle.properties` in the root directory of the project and check that the following properties are set correctly:
    ```properties
    pokemmo.executable=${HOME}/.local/share/pokemmo/PokeMMO.exe
    pokemmo.workingDir=${HOME}/.local/share/pokemmo/
    ```
2) Open a terminal and navigate to the root directory of the project.
3) Run the patcher using Gradle:

| Windows                    | Everything else          |
|----------------------------|--------------------------|
| `gradlew.bat :patcher:run` | `./gradlew :patcher:run` |

This writes a patched copy of the client to `patcher/build/PokeMMO-openmmo.exe` and starts it.
The original executable is never modified.

### Connecting to a remote OpenMMO server

Releases include `openmmo-patcher.zip` for testers without the source tree.
It requires Java 25 or newer. Extract it, download the server's game public
key as `game.public.pem`, then double-click `bin/openmmo-patcher.bat`.

The launcher remembers the selected server, client and public key. Select the
public demo or enter a custom login address, then choose **Play OpenMMO**.

The same launcher remains available from a terminal:

```powershell
.\bin\openmmo-patcher.bat `
  --login-host login.openmmo.dev `
  --login-port 2106 `
  --game-public-key .\game.public.pem `
  --client "C:\Program Files\PokeMMO\PokeMMO.exe" `
  --working-dir "C:\Program Files\PokeMMO"
```

The remote server must publish its numeric game address through the login
server. The patcher accepts these environment variables as alternatives:

| Option | Environment variable |
| --- | --- |
| `--login-host` | `OPENMMO_LOGIN_HOST` |
| `--login-port` | `OPENMMO_LOGIN_PORT` |
| `--game-public-key` | `OPENMMO_GAME_PUBLIC_KEY_FILE` |
| `--client` | `OPENMMO_CLIENT` |
| `--working-dir` | `OPENMMO_WORKING_DIR` |
| `--output` | `OPENMMO_PATCHED_CLIENT` |

Arguments after `--` are passed to the patched client.

## How It Works
PokeMMO ships as a GraalVM native image, so there is no bytecode left to instrument at class load time.
Earlier versions of this module used a Java agent for that, which no longer works.

Instead the patcher edits the executable itself.
String constants of a native image live in its image heap and are stored as plain Latin-1 bytes, so the base64 encoded public keys can be found and swapped with a byte search.
The heap keeps the string length in a separate field, so a replacement has to be exactly as long as the original.
Both the PokeMMO keys and ours are `secp256r1` public keys in X.509 form, so their base64 always has the same length.

### Redirecting the login server
The client takes the login server address from a signed feed it downloads at startup and refuses to start without one, so `FeedServer` serves its own on a random loopback port.
It has to be HTTPS because the native image only enables that protocol, so the client is launched with a trust store holding a certificate generated for `127.0.0.1`.
The two RSA keys the client checks the feed signature against are patched to ours.

Feed mirrors are redirected by swapping only the `https://<host>` part of the url and padding with slashes that the path absorbs.
`https://127.0.0.1:<port>` is as wide as `https://dl.pokemmo.com`, so the port stays four digits. A shorter mirror gets port 1 and the client moves on to the next one.

The compiled in `loginserver.pokemmo.com` is only a fallback, but it is patched too.
Hostnames cannot be padded because Java rejects NUL and whitespace in them, so the patcher writes `[0:0:0:0:0:ffff:7f00:1]` instead, which parses straight to `127.0.0.1`.

### Running the patched client
The patched bytes are written to a copy in the build directory, started with the working directory set to `pokemmo.workingDir` so the client finds its data, config and ROMs.

The keys come from the `:keys` module and are copied into the resources of this module. If no keys have been generated, gradle will call the appropriate task to generate them. More infos about that can be found in the [keys module](../keys/README.md).

## Updating for New PokeMMO Public Keys
If the PokeMMO public keys or the login server hostname change, for example after a game update, the patcher fails with a message that a patch had no match.
Update the constants at the top of `kotlin/de/fiereu/openmmo/patcher/Launcher.kt` with the new values.

To find them, search the executable for the prefix all `secp256r1` public keys share:
```sh
grep -a -o "MFkwEwYHKoZIzj0CAQYIKoZIzj0DAQcDQgAE[A-Za-z0-9+/=]*" PokeMMO.exe
```

The client uses one key for game packets and one for chat packets.
To tell them apart, load the executable in a disassembler like [Binary Ninja](https://binary.ninja/) or [Ghidra](https://ghidra-sre.org/) and look at what the surrounding code verifies.

The login server hostname sits next to the config key `loginserver.network.client.host` in the same string table and can be found the same way:
```sh
grep -a -o -E "[a-z0-9.-]+\.pokemmo\.(com|eu)" PokeMMO.exe | sort -u
```

The feed signing keys are RSA and the mirrors are plain urls:
```sh
grep -a -o "MIIBojANBgkqhkiG9w0BAQEFAAOCAY8A[A-Za-z0-9+/=]*" PokeMMO.exe | sort -u
grep -a -o -E "https://[a-zA-Z0-9.-]+/[a-zA-Z0-9./_-]*main_feed\.(txt|sig256)" PokeMMO.exe | sort -u
```
